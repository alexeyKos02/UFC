# Лига игроков UFC

Сайт лиги: ручная запись результатов с подтверждением обоими игроками, турниры на вылет, пояса, рейтинг и статистика.

Стек: Vue 3, TypeScript, Vite, Vue Router, FastAPI, SQLAlchemy, Alembic, PostgreSQL, Docker Compose.

## Запуск

Нужен Docker с Compose.

```bash
cp .env.example .env
```

Откройте `.env` и задайте `POSTGRES_PASSWORD`. Затем:

```bash
docker compose up --build -d
```

Сайт откроется на http://localhost:8080 (порт задаётся в `APP_PORT`). Миграции применяются при старте бэкенда. Документация API: http://localhost:8080/api/docs.

База и загруженные изображения лежат в томах `postgres_data` и `uploads_data` и переживают `docker compose down` и перезапуск. Удаляет их только `docker compose down -v`.

### Первый владелец

Роль владельца назначается только при настройке, через консоль. Пароль будет запрошен в терминале:

```bash
docker compose exec backend python -m app.cli create-owner --login owner
```

Если логин уже зарегистрирован, пользователь становится владельцем, а пароль заменяется на введённый.

### Демоданные

```bash
docker compose exec backend python -m app.cli seed-demo
```

Команда безопасна при повторном запуске: если демо-логины уже есть, она ничего не меняет.

Пароль всех демо-аккаунтов: `demo12345`.

| Логин | Роль |
|---|---|
| `demo_owner` | Владелец |
| `demo_admin` | Админ |

## Проверки

Тесты идут на настоящем PostgreSQL, потому что проверяют замки и ограничения базы. База `<POSTGRES_DB>_test` создаётся автоматически, рабочие данные не затрагиваются.

```bash
docker compose --profile test run --rm --build tests
```

Сборка фронтенда с проверкой типов:

```bash
docker compose build frontend
```

Без Docker:

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
TEST_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@localhost:5432/ufc_test .venv/bin/python -m pytest -q
```

```bash
cd frontend && npm ci && npm run build
```

## Как проверить MVP на демоданных

1. **Регистрация и бой.** Зарегистрируйте нового пользователя на `/register`. В профиле загрузите аватар и фото в полный рост. На странице «Бои» нажмите «Записать бой», выберите `Волк`, укажите победителя и нажмите «Отправить и подтвердить». Очки и статистика не изменились. Войдите как `volk`, в «Мои бои» подтвердите запись: бой учтён один раз.
2. **Спор.** Запишите бой против `orlov`, под `orlov` нажмите «Оспорить» и укажите причину. Инициатор исправляет запись в «Мои бои»: на странице боя видно, что подтверждения первой версии не действуют. Бой учтётся после подтверждения новой версии. Готовый пример спора ждёт `volk`.
3. **Турнир.** Под `demo_admin` в админке откройте регистрацию для черновика «Летний чемпионат» или используйте «Кубок последнего места»: в нём осталось одно место, второй желающий получит отказ. Запустите турнир кнопкой «Запустить». Сетка создаётся один раз, при нечётном числе участников в первом раунде появляются проходы.
4. **Сетка и пояс.** В «Кубке железного кулака» пять участников и идут бои. Участник матча вносит результат на странице турнира, соперник подтверждает, победитель проходит на одну позицию. Бои турнира не меняют очки рейтинга, но учитываются в статистике. После подтверждённого финала победитель получает очки, заданные при создании турнира, а чемпион получает активную иконку. Пример смены чемпиона: профиль `tigr` (серая иконка пояса новичков) и профиль `bars` (активная).
5. **Промо и роли.** В разделе «Промоплашки» создайте и опубликуйте анонс боя и бойца недели. Под `demo_owner` в разделе «Роли и блокировки» назначьте админа и заблокируйте игрока: его сессия завершится сразу, а бои и пояса останутся в истории. Пример: профиль `ten`, «Тень».
6. **Рейтинг.** Очки считаются по Elo: старт 1000, победитель забирает у проигравшего `round(40 · (1 − E))`, где `E = 1 / (1 + 10^((Rсоперника − Rпобедителя) / 400))`, но не меньше 1. Равный бой даёт ±20, победа над соперником сильнее на 200 очков — +30, над слабее на 200 — +10. Формула, сумма очков и общий ранг проверяются автотестами из `backend/tests/test_rating.py`. На странице боя видны места и очки до начисления. В таблице у каждого игрока свой номер: при равных очках выше тот, кто лучше в личных встречах с равными по очкам, затем у кого победы в этих боях убедительнее (нокаут, сабмишен, решение), затем по алфавиту. Для апсетов равные очки по-прежнему дают одно место.
7. **Ручная корректировка.** В разделе «Рейтинг» есть список апсетов. Добавьте корректировку к бою `Лис` — `Кракен`, форма покажет итог для обоих. Измените и отмените её, в журнале останутся автор, причина и значения. Пример уже проведённой корректировки: бой `Зубр` — `Волк`.
8. **Чемпион и спецместо.** В таблице «Игроки и рейтинг» действующий чемпион основного пояса стоит первым с символом короны вместо номера, остальные нумеруются с №1. Это только отображение: очки и апсеты считаются по местам по очкам, где чемпион участвует наравне со всеми. В разделе «Рейтинг» закрепите №1 за игроком с четвёртым местом по очкам. В таблице он стоит сразу под чемпионом. Пометку «Спецместо» видят только админ и владелец, обычные игроки видят только номер. При победе над лидером по очкам он получит очки по Elo, как и все: спецместо на них не влияет. Закрепить тот же номер за другим игроком нельзя, форма покажет, за кем он. После снятия игрок возвращается на место по очкам.
9. **Бой до игры и голоса.** В форме «Записать бой» выберите «Бой ещё не состоялся». Бой появится в разделе «Предстоящие бои» на странице «Бои» и в «Мои бои» у обоих участников. Зрители голосуют за бойца, сами участники не голосуют. Голосование идёт до внесения результата, а итог голосов виден и в карточке прошедшего боя. Голосовать можно также за назначенный титульный бой и турнирный матч с известной парой.
10. **Титульный бой.** Карточка боя `Кракен` — `Тигр` уже в «Мои бои» у обоих. Результат вносит любой из них. После второго подтверждения начисляются очки, а победитель получает основной пояс или сохраняет его с пометкой о защите. Назначать бой может только админ или владелец.
